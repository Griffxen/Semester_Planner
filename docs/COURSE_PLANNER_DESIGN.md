# 课表模板设计器、多课表与补课设计

日期：2026-10-22。状态：本地实现及核心验收完成，尚未推送或部署。

## 1. 目标与已确定的选择

将现有单份公共课表扩展为多份独立维护、独立授权的课表模板，提供可视化设计器；课程拥有多个固定时段，个人可以合并导入多份模板，并为某次课安排补课或额外加课。

已确认：

- 使用独立设计器页面，电脑显示课程列表、周课表和编辑表单；手机按天查看并使用表单编辑。
- 第一版采用点击定位和表单编辑；时间同时支持节次和具体时刻。
- 每份模板独立设置作息、停课日期、查看导入权限及协作编辑权限；授权由管理员管理。
- 用户可以导入多份模板，更新前预览差异，默认保留个人修改。
- 撤销模板授权后保留已导入副本，停止获取源模板及其更新。
- 补课同时支持关联原课和额外加课；手动补课、调课可以在提示确认后安排到停课日期。
- 取消关联补课后原课仍停课；恢复原时间上课是独立操作。
- 旧数据按同名生成归并候选，用户确认一次后建立共同课程 ID；以后按 ID 归属。

第一版沿用现有个人学期起始日、18 周及单双周规则。模板保存周次规则，导入后按个人学期起始日展开；本次不扩展为多学期管理、自动排课、拖动排课或图片识别导入。

## 2. 设计器与使用流程

### 模板列表与设计器

“课程安排”提供我的课程、可用模板、临时调整三个入口。管理员在模板列表中新建、复制、重命名和归档模板；普通用户只看到已获授权的模板，协作者在有编辑权限的模板上获得编辑入口。

设计器使用独立路由 `/timetables/`，通过模板 ID 打开具体模板。电脑布局为左侧课程列表、中间周课表、右侧编辑表单；顶部显示模板名称、未保存状态和保存按钮。同层标签切换课程安排、作息时间、停课日期、权限；无权限的标签不显示。

- 新建一门课程后，可添加多个时段。时段填写星期、起止周、单双周、教室，以及节次或具体起止时刻。
- 点击周课表空白处新增时段并预填星期、时间；点击课程块编辑该时段；课程列表选择一门课时高亮其全部时段。
- 周次选择器预览具体某一周，正确区分单双周和起止周。重叠课程并排显示，提示冲突但允许确认后保存；不能只按星期与时间判断单双周课程冲突。
- 合并和拆分课程在课程列表中操作。合并保留各时段身份，拆分仅改变时段所属课程，不复制课次、备注或作业。
- 编辑保存在页面草稿中，最终统一提交；离开未保存页面时提示。保存失败或版本冲突时保留草稿。
- 手机显示日期切换、当天课程和课程列表，编辑表单单独打开；不将电脑三栏整体缩小。

### 作息时间

每份模板可维护若干节次，各自有编号、开始及结束时刻。课程选择连续的起止节次，或切换为直接填写时间。均校验结束晚于开始，不支持跨午夜上课。

节次课程保存节次引用及解析后的具体时刻；直接填写的课程不依赖节次。修改作息后，设计器列出受影响的节次课程，确认保存时一并更新；已有个人副本通过下一次导入差异处理。不能直接删除被引用的节次，需先修改对应课程。单次调课、补课保存具体时刻，不随以后作息变化。

### 个人课程管理

个人编辑复用设计器的课程及多时段表单，提供本人课程、来源课表和临时调整查看；源模板权限始终在模板管理处设置。课程列表按门统计，课程详情合并展示所有时段的课次，并提供添加补课、备注及作业入口。

## 3. 数据身份、权限与导入更新

### 数据模型

使用“课表 → 课程 → 固定时段 → 课次”结构：

| 对象 | 关键内容及身份 |
| --- | --- |
| 课表模板 | `template_id`、名称、版本、课程、作息、停课日期、归档状态 |
| 课程 | `course_id`、课程名称、多个固定时段；改名不改变 ID |
| 固定时段 | `slot_id`、星期、时间、教室、周次规则、时间输入方式；改时间不改变 ID |
| 课次 | `occurrence_id`、所属课程/时段、原日期和时间、实际日期和时间、状态、备注与作业 |
| 导入来源 | 模板 ID、导入版本、上次源数据快照、源课程/时段 ID 到个人对象的映射 |

当前旧 `course_id` 实际是时段标识，迁移时原样保留为 `slot_id`。旧接口的 `course_key` 继续表示这个时段，不重新解释为新版课程 ID。常规课次身份由时段 ID 与原始日期构成，调课和关联补课后不变；额外加课使用独立生成的稳定 ID。同一门课同一天两次上课仍是两个课次。

个人课程、补课和注释以用户为归属。合并课程保留旧课程 ID 到保留课程 ID 的映射，导入来源继续按原课程/时段 ID 匹配；不因归并再次导入出重复课程。复制模板产生新模板及新课程、时段 ID，保留原模板不变。

### 权限

- 所有全站管理员可以管理模板和授权。每份模板分别设置可查看导入账号、可编辑账号；编辑权限同时包含查看导入权限。
- 协作者只能编辑指定模板的课程、作息和停课日期；不能修改授权、归档模板或获得其他管理员能力。
- 新模板默认仅管理员可访问。迁移出的默认模板保留现有所有普通账号可读可导入的行为。
- 展示账号继续只读取个人分享投影，不获得模板管理或导入能力。
- 服务端统一校验列表、详情、编辑、导入预览和导入提交权限；旧接口采用相同校验。
- 撤权和模板归档阻止后续读取、导入及更新，已导入个人副本仍可使用、编辑及按原有个人分享规则展示。

### 多来源导入与更新

导入创建个人快照，不实时联动修改个人日程。同一来源重复导入执行更新，不重复添加；不同来源同名课程不自动合并，可由用户明确归并。

更新以“上次源快照、当前源模板、当前个人副本”比较，按课程和时段 ID 展示新增、修改、移除及冲突：未被个人修改的字段跟随源变化，个人修改的字段默认保留，可明确选择覆盖。来源的作息和停课日期也进入预览，停课日期仅作用于该来源的课程。

源模板移除的时段若未被个人修改且无个人课次记录，可移出常规排课；有调课、补课、备注或作业记录时保留归档对象及原始安排快照，标明“来源已移除”，个人记录可继续查阅。个人新增课程及其他来源内容不受影响。个人确认保留的固定时段继续正常排课。

相同保护适用于所有排课规则变化，包括修改星期、起止周、单双周和个人学期起始日。变更预览列出将不再由新规则生成且已有个人记录的课次，按原 `occurrence_id` 保存原始安排快照并保留查阅入口；有效调课和补课仍按实际安排显示。无个人记录的普通派生课次按新规则重新展开。个人编辑和学期设置变更也必须调用这套保留逻辑。

保存模板、个人编辑、权限和导入均检查版本。预览与提交之间源模板、权限或个人副本变化时，拒绝过时提交并要求重新预览；不覆盖草稿。新增课表存储、授权及来源快照使用 SQLite，课程和时段作为带版本的课表结构保存，替代旧扁平数组作为唯一数据源。

## 4. 补课、接口与兼容迁移

### 补课规则

- **补原有课：** 在某次课详情或课程的停课记录中选择“安排补课”，填写日期、时间和地点；原时间不再计入实际占用，补课沿用原课次身份及备注、作业。每个原课次最多有一个有效关联补课，再次安排编辑现有补课。
- **额外加课：** 在课程详情选择“添加额外课程”，创建独立课次及独立备注、作业，不影响任何常规课次。允许同一天有多次额外课。
- 停课记录包含手动取消及节假日抑制的常规课次，能从中选择补课来源。节假日抑制不删除原课次身份。
- 取消关联补课仅撤下补课安排，原课保持取消；“恢复原课表”另行确认，恢复后仍遵守该来源停课规则。取消额外加课保留其记录和注释，允许恢复，不计入实际占用。
- 普通周课遵守所属课表的停课日期；明确设置的调课或补课优先于停课规则。保存时列出停课提示和时间冲突，确认后允许安排，不再被展开逻辑隐藏。
- 关联原课时默认继承其地点；额外加课地点可空。补课和调课使用北京时间，第一版限定在个人当前 18 周学期范围内。

### 接口边界

- `/api/timetables` 及其按 ID 的详情接口负责模板列表、新建、读取、保存和归档；独立的 `permissions` 子接口负责授权。
- 模板的 `import-preview`、`import` 子接口负责差异预览和按选择导入，携带源及个人版本。
- `/api/course-plan` 负责新版个人课程结构及编辑；`/api/course-makeups` 负责关联补课和额外加课的创建、修改、取消、恢复。
- 现有课程例外、备注接口增加稳定课次 ID 定位方式，兼容旧 `course_key + date`；本人课次才能修改。关联补课复用原课次的例外状态，额外加课独立存储。
- 保存接口返回规范化内容和新版本；版本冲突返回 `409`，无权操作返回 `403`。所有写操作继续校验会话及 CSRF。

### 迁移与消费端

1. 备份后执行有版本、事务化且可重复运行的迁移：旧公共模板成为默认模板，全局停课日期复制到默认模板；旧个人课表保留为个人快照，原时段 ID、例外、备注与作业保持关联。
2. 首次先按一旧条目一个时段无损迁移，提出同名课程归并候选；管理员确认模板候选、个人确认自身候选后建立课程归属。模板归并映射随下一次导入进入个人副本，不静默改动个人数据。
3. 保留扁平 `timetable`、`course_dates` 兼容投影，现有看板和只读消费端继续读取实际课次。冻结 `/legacy/` 资源不改；旧 `/api/timetable` 只映射默认模板，旧导入只更新默认来源，不能替换个人全部来源。无法无损表达新版结构的旧模板写入返回 `409`，提示使用新版设计器。
4. 桌面、手机、时间分布、冲突提示、分享、Dashboard 及自选导出共用课次展开结果；取消课次不计入实际占用，补课按实际日期显示，私人备注与作业继续按既有分享边界过滤。
5. 自选导出采用稳定课次 ID，并兼容原排除键。完整 JSON 归档升级为 `format: 2`，包含个人课程、来源快照、停课规则、例外、补课、备注及作业；不包含无权访问的源模板最新内容。维持归档用途，本次不新增备份恢复导入。

## 5. 实现顺序与验收

实现依次完成数据身份及迁移、模板与权限 API、个人导入差异、可视设计器、补课及消费端联调。每一步保留兼容投影，最终以完整流程验收。

必要回归与界面验收：

- 一门课每周两次、同一天两次、单双周及不同起止周，统计和课次均正确；改名、改时、改星期、缩短周次、改变学期起始日、合并及拆分后已有记录仍可找到。
- 设计器新建模板、配置节次、添加多个时段、切换指定周预览、修改作息、保存及刷新；手机可完成对应表单流程，未保存退出和版本冲突保留草稿。
- 两份模板独立编辑、授权和停课；普通使用者、协作者、管理员、展示账号各自只能执行允许的操作；直接请求接口不能越权。
- 导入两份模板，修改其中一份后更新，只比较对应来源；重复导入无重复，个人修改默认保留，源删除及撤权后个人记录保留。
- 节假日隐藏的原课可以补课；补到另一个停课日期确认后可见；关联补课无重复占用，备注及作业跟随；取消后原课仍停课，恢复需独立操作。
- 额外加课不影响常规课，取消和恢复不丢注释；分享、Dashboard、导出和时间分布与实际课次一致且不泄露私人字段。
- 使用含旧例外和注释的数据库副本验证迁移前后记录关联、课次数量及幂等性；既有回归通过，冻结旧版资源哈希不变，旧接口无法覆盖多来源个人课表。

本地实现已完成。78 项 Python 回归、7 组 Node 检查通过；真实浏览器已完成创建模板、一课两时段、作息及停课设置、差异导入、停课补课与手机表单核心流程。现有本地数据库仅在临时副本上执行迁移及重复初始化，原文件哈希保持不变。提交、推送及服务器部署遵循后续明确请求。
