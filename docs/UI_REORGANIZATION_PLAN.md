# 学期手记界面重整方案

评审日期：2026-10-13（北京时间）。设计原则补充与首版实现：2026-10-14。下文保留评审与设计依据；已实现范围及过渡方式见 [新版前端与过渡](FRONTEND_TRANSITION.md)。

## 已确认的设计原则（2026-10-14）

以下三项由用户明确确认，约束后续草图、实现与验收；其余布局建议仍可讨论。

1. **控制纵向长度，尤其是长任务块。** 持续时间长不增加块高，名称、备注和节点多也不能让总览中的块无限增高。任务块采用有限行数的摘要：标题、必要时间信息、至多一条近期节点；更多信息通过详情查看。桌面同一视图中的长任务保持统一高度，具体行数与高度用草图确定。密集任务采用紧凑排布和明确的展开入口；手机按日查看，避免默认展开整学期或把所有长期任务逐项铺满首页。
2. **关键按钮采用二次滑块确认。** 首次点击关键按钮只进入确认状态，在原按钮位置通过滑动完成第二次操作；保留角落里低调的“直接确认”作为备用路径。它只确认当前待执行操作，使用相同的校验与权限边界，不是另一个操作入口。确认对象和后果应在当前上下文中可知；解决文案不清楚或遮挡问题时，保留这套机制，不改为普遍弹出确认框，也不取消角落备用入口。
3. **展示和操作合理分级，同时限制入口深度。** 总览展示摘要，点击一次进入详情；常用编辑、调时和完成操作在详情中直接可达。同一对象的内容、时间、节点等可通过同层标签页切换，复杂创建可分步骤，低频或高级配置再展开。常用操作在进入详情后最多再经过一次入口选择即可到达操作界面，二次滑块确认单独计算；避免连续多层折叠菜单和弹窗套弹窗。每层都有明确的标题、返回路径与当前状态。

这三项共同要求：总览保持紧凑，详情承担完整信息，操作按需出现。不能为压缩首页而把常用信息藏进多层菜单，也不能为减少点击而把所有字段和按钮堆在一页。

**已确认的具体布局要求：视图切换与“定位今天”常驻。** 当前“学期 / 今日”切换及“定位今天”所在栏应作为滚动期间始终可见的导航栏，而不是随内容离开的表头。后续如增加“本周”，也放在这条常驻导航中。桌面和手机均保持核心按钮可达；搜索及其他筛选可按空间分级，不要求全部挤入常驻栏。实现应针对实际滚动容器保持常驻，并为导航预留空间，避免遮挡日期、任务和滚动定位目标；弹窗及其确认控件仍位于导航上层。

**已确认的整理范围：菜单名称与整套图标。** 系统梳理导航、菜单和操作按钮的名称，按用户看到的功能命名，同一功能跨页面使用同一名称；避免“更多”等入口承担过多不相关功能。重新配置一组风格统一的图标，覆盖视图、定位、任务、课程、手记、分类、分享、导出、设置和账户。具体名称、图标来源和样式尚待草图比较后确定。

图标系统采用一致的线条、尺寸、视觉重量与对齐规则；优先使用可在项目中维护的 SVG 图标，并统一管理。相同动作复用同一个图标，不继续混用 Unicode 字符、emoji 和不同风格符号。导航和常用操作保留文字名称；只有关闭等含义明确、空间受限的按钮可以只用图标，并提供可访问名称及必要的提示。图标应表达功能，不以装饰为主要目的，也不能增加任务块高度。

**账户操作的分级与独立身份验证。** 根据用户反馈，账户设置不再通过下拉菜单选择修改用户名、修改密码等不同操作。推荐使用同层标签页“个人资料 / 修改用户名 / 修改密码”，各页只显示相关字段、说明和操作；管理员的创建账户、重置密码等管理功能进入独立管理入口，具体标签名称在命名表中统一。

需要验证当前身份的操作采用专门的“验证身份”窗口，不把当前密码混在业务表单中。先填写修改内容，再在提交流程中进入验证；窗口说明目标账户、待执行操作和必要的影响。验证窗口暂时替代当前编辑窗口作为唯一可交互界面，避免多层弹窗叠加；验证取消或失败时保留原表单内容，允许返回编辑，且不执行变更。身份验证必须由服务端检查，界面分离不能降低原有权限要求；验证成功后才能执行当前操作，执行前仍需检查提交内容和权限。

身份验证与二次滑块用途不同：身份验证确认操作者身份，滑块确认表达对当前操作的执行意图并防止误触。具体流程在草图中统一安排，避免验证成功后又出现重复确认窗口；需保护的关键按钮仍保留二次滑块与角落备用确认。当前密码不跨操作保留，退出验证后清除；新密码只出现在修改密码页，不能与验证身份所需的当前密码混淆。是否支持短时复用验证、验证有效期和凭据机制尚未决定，实施时单独设计，不默认长期免验证。

## 4. 推荐的信息结构

主导航采用“今天 / 本周 / 学期”。这只是建议，尚未决定或实现默认视图；推荐默认“本周”，兼顾课程和跨日准备任务。

- **今天**：顶部是当天日期与添加任务；按时间排序的课程/定时任务为主体，当天日期任务和进行中的长期任务采用同层分区或标签，避免全部默认展开。已完成项目折叠。近期截止/节点与手记通过可见的同层入口查看，不将完整内容一起堆在首页。
- **本周**：上一周、回到本周、下一周；桌面保留七日布局，跨日任务占独立轨道；手机按日期显示议程。长期任务只显示标题、区间、最近未完成节点，完整节点在详情查看。
- **学期**：保留 18 周总览，默认摘要密度，支持按周展开；用于考试、汇报和长期准备的远期安排。课程默认不铺满全学期。
- **课程**：个人课表、临时调整记录、公共模板预览；管理员模板编辑属于管理入口。
- **账户菜单**：分类管理、学期设置、分享管理、导出、账户资料、退出。主题选择收在外观设置中。

桌面统计压缩成一行，不占据大面积首屏；手机优先显示今日/本周内容，统计和分类作为可展开区域。空白鼓励文案留在真正无安排的空状态，常规界面减少重复装饰文字。

任务块高度由视图的摘要规则决定，与任务持续天数、备注长度和节点总数无关。长标题截断并可在详情查看全文；节点只显示一条近期摘要及更多节点数量，完整列表在详情节点页展示。每个区域有明确的内容容量和展开方式，不能依靠任意增高任务块解决信息增加。

## 5. 时间概念与视觉规则

保持三种时间的独立性，并在页面使用同一套名称：

| 概念 | 解释 | 展示位置 |
| --- | --- | --- |
| 计划时间 | 准备或执行的开始与结束，可调整 | 日历、今天/本周列表、详情 |
| 截止时间 | 主任务最终交付时间，移动计划不自动改变 | 独立截止标记、近期截止列表、详情 |
| 关键节点 | 阶段性目标及独立完成状态，移动计划不自动改变 | 最近节点摘要、近期节点列表、详情时间线 |

节点和主任务完成状态仍独立，界面明确这一点。不根据整项任务完成自动改写节点，不把跨日日期任务解释为全天占用，也不将节点定义为子任务重新建模。

分类颜色只负责区分类别；紧迫程度通过文字和截止标记表达，避免整条任务同时承担“类别颜色”和“紧急颜色”两种含义。完成状态使用可读的状态标记，减弱显示时仍保证文字可辨认。

## 6. 任务与确认流程

统一任务详情入口：标题、状态和关键时间为摘要，完整内容、时间安排和节点通过同层标签页展示，操作随当前内容出现。编辑、调时和完成入口直接可达，避免先展开多级菜单。内容编辑和调时共享关闭、错误、保存反馈规则；可以继续保持分别保存，以免扩大后端改动。

创建任务先展示“名称 + 计划时间”，分类提供默认值，DDL、节点、简称和备注分组为可选内容，最多一层展开。如果保留两步，第一步只处理必要信息，第二步展示精简摘要并提供直接返回修改入口，避免反复回退查字段。

确认按照后果设计：普通查看与无修改关闭直接完成；未保存改动关闭时明确“继续编辑 / 放弃修改”；删除、课程取消/恢复、权限变更等关键操作展示具体对象和影响。关键按钮首次点击进入原位确认状态，第二次以滑块完成；角落保留低调的“直接确认”备用入口，不与主操作争夺视觉注意力。操作对象与后果在原位或当前面板中说明，不能只剩角落的按钮。退出确认或切换操作时清除旧的待确认状态，备用入口与滑块始终指向同一当前操作。保存中的按钮、保存成功、失败和版本冲突使用统一反馈；本轮只提出规则，没有对写入流程作实测结论。

## 7. 筛选、空状态和只读页面

所有视图保留清晰的筛选摘要和“清除筛选”。统计要么明确为全学期，要么跟随当前范围；禁止没有说明地混用。搜索需要先决定覆盖任务还是全日程，推荐默认任务搜索，同时涵盖简称、节点名；若扩展到课程和手记，应显示结果类型。

区分无安排、筛选无结果、未导入课表、无分享授权、今天超出授权范围、加载失败六种状态。每种状态解释原因；只读页只能提供清除筛选、日期导航等只读操作。

分享管理先显示“谁在看、可以看什么、日期范围、当前状态”，然后进入权限编辑。预览明确说明使用已保存设置；仅占用模式去掉缺乏意义的任务搜索及完成筛选，并说明日期安排不代表全天忙碌。Token 配置进入独立高级区域。

## 8. 实施顺序与验收

1. **先确认布局和规则**：确定默认视图、三个时间概念的名称、统计范围、搜索范围、详情形式。产出桌面和手机的首页/详情草图，不修改数据结构。
   同时制作“功能 → 菜单/按钮名称 → 图标”的完整对应表，在真实尺寸草图中比较整套图标的辨识度与对齐效果，确认后再替换。
2. **整理阅读体验**：解决顶部遮挡，增加本周入口，整理今天排序、近期节点、筛选摘要、空状态及手机分区。先使用固定样例在本地验收。
3. **统一操作体验**：整理任务详情、内容编辑、调时、关闭与确认，再整理课表、分享和设置。只有明确授权后才在隔离数据上验证写入。
4. **整理前端结构**：按状态与筛选、日期/截止、课程、任务详情、确认、渲染、导出划分职责。逐步归并重复 CSS 覆盖和重复弹窗规则；不在一轮中重写数据库或更换框架。PNG 使用独立渲染路径，后续需专门保证与页面的信息口径一致。
5. **审核后发布**：按阶段提交、审阅；获得部署授权后备份并发布，生产仍先做只读验收。

验收清单：

- 390px、768px 与常规桌面宽度下，导航和主题入口不重叠；弹窗关闭和主要操作可见。
- 页面滚动到中段和末尾时，视图切换与“定位今天”仍可见、可操作；定位后的日期与任务不被常驻栏遮挡，弹窗及确认控件不被导航覆盖。
- 菜单名称与功能一致，同一动作跨页面命名和图标一致；整套图标风格统一，在浅色、深色和手机尺寸下清楚可辨，只用图标的按钮具备可访问名称。
- 默认页直接看到当前范围；今天页的课程和定时任务按时间排序，长期任务有独立位置。
- 长任务块不因持续天数、长标题、长备注或节点数量增加而无限增高；多节点与密集任务仍保持既定摘要高度和可见的展开入口。
- 计划起止、最终截止、节点时间各自可辨；跨周/学期外、无 DDL、多节点、已完成等状态都能正确阅读。
- 当前筛选与统计范围清楚；无匹配不会呈现为“今天没有安排”；清除筛选有明确入口。
- 未修改关闭不确认；关键按钮的第一次点击不执行写入，原位第二次滑动完成确认；角落低调的备用直接确认保留，且始终确认同一当前操作。
- 总览点击一次到详情；常用操作在详情中直接可达，或最多再经过一次入口选择到达操作界面；完整信息通过同层标签或至多一层展开查看。
- 修改用户名与修改密码使用同层独立入口，切换后仅显示对应字段；管理员操作不混入个人设置的操作下拉菜单。
- 需要鉴权的操作使用独立身份验证窗口，清楚显示待执行操作；取消或验证失败不会提交，原业务表单内容保留，验证密码清除。鉴权是必要提交步骤，不用于增加普通阅读或编辑的导航层级。
- 所有者、普通账户、展示账户、仅占用预览和管理员的可见操作符合各自职责。
- 浅色、深色与键盘焦点在后续完整验收中覆盖；写入验证只使用获准的隔离数据。
