## 3. 主要问题及处理优先级

| 优先级 | 现状与证据 | 使用负担 | 重整方向 |
| --- | --- | --- | --- |
| P0 | 现场：390px 顶部主题按钮与“更多”入口重叠，实际发生误触 | 基础导航不可靠 | 将主题入口放进设置菜单，或给顶部按钮预留独立空间；取消悬浮按钮覆盖导航 |
| P1 | 现场：总览刷新后从第 1 周开始；查看当前周需要“定位今天” | 每次日常查看多一个步骤，已过去的空白占据首屏 | 增加以当前周为中心的周视图；学期总览承担远期规划 |
| P1 | 现场：今天页先显示课程，再显示任务；分钟任务与课程不按同一时间轴排序，长期任务也占据主列表 | 不容易判断接下来做什么 | 将课程和定时任务合并为时间顺序；日期任务和长期任务分区 |
| P1 | 现场：关键节点已经出现在条块和任务详情；顶部“未来 7 天截止”只有主任务 DDL 口径，源码只读取 `due` | 阶段节点与最终截止混用，近期要完成的节点不显眼 | 建立独立的近期截止/节点列表，标明类型；统一统计口径 |
| P1 | 现场：总览是 7 列日期格加每周持续任务条；手机变成逐日长列表，持续条块排列在整周后 | 当天任务与进行中的任务要跨区域寻找 | 桌面周视图呈现日期与持续任务；手机改用按日议程和独立进行中分区 |
| P1 | 现场：仅打开分类管理、不做修改，关闭仍要求确认；确认按钮位于屏幕右上角，与弹窗分离 | 退出查看也被打断，确认对象不清楚 | 无修改直接关闭；有修改才提示放弃；确认内容与按钮放在当前弹窗内 |
| P2 | 现场：编辑内容、调整时间分属两个弹窗；新建第一步先填写名称、简称、DDL、节点、备注，再设置计划 | 一个任务的相关字段被分散；简单任务也面对很多选项 | 统一任务详情入口；基础创建只要求名称与计划，其他字段渐进展开 |
| P2 | 现场：搜索无匹配时任务消失，课程与手记入口仍在，统计数字不变；源码搜索仅覆盖标题、备注 | 不清楚是在搜任务还是所有日程，不清楚数字是否受筛选影响 | 明示搜索对象、结果数与清除入口；标记“全学期统计”，区分全局和当前筛选 |
| P2 | 现场：今天页仍显示课程范围选择；“定位今天”会切回学期总览 | 同名操作跨视图的结果不容易预期 | 按视图显示有效控件；今天页不显示周范围，定位在当前视图内完成 |
| P2 | 现场：设置与导出有外层“更多”及内层折叠；打开后分类区域出现内部滚动 | 常用入口藏得深，侧栏有多层滚动 | 日常导航与低频设置分开；课程单独进入，账户菜单集中低频操作 |

## 4. 推荐的信息结构

主导航采用“今天 / 本周 / 学期”。这只是建议，尚未决定或实现默认视图；推荐默认“本周”，兼顾课程和跨日准备任务。

- **今天**：顶部是当天日期与添加任务；主体依次为按时间排序的课程/定时任务、当天日期任务、进行中的长期任务。已完成项目折叠。右侧或底部显示未来 7 天截止和节点、当天手记。
- **本周**：上一周、回到本周、下一周；桌面保留七日布局，跨日任务占独立轨道；手机按日期显示议程。长期任务只显示标题、区间、最近未完成节点，完整节点在详情查看。
- **学期**：保留 18 周总览，默认摘要密度，支持按周展开；用于考试、汇报和长期准备的远期安排。课程默认不铺满全学期。
- **课程**：个人课表、临时调整记录、公共模板预览；管理员模板编辑属于管理入口。
- **账户菜单**：分类管理、学期设置、分享管理、导出、账户资料、退出。主题选择收在外观设置中。

桌面统计压缩成一行，不占据大面积首屏；手机优先显示今日/本周内容，统计和分类作为可展开区域。空白鼓励文案留在真正无安排的空状态，常规界面减少重复装饰文字。

## 5. 时间概念与视觉规则

保持三种时间的独立性，并在页面使用同一套名称：

| 概念 | 解释 | 展示位置 |
| --- | --- | --- |
| 计划时间 | 准备或执行的开始与结束，可调整 | 日历、今天/本周列表、详情 |
| 截止时间 | 主任务最终交付时间，移动计划不自动改变 | 独立截止标记、近期截止列表、详情 |
| 关键节点 | 阶段性目标及独立完成状态，移动计划不自动改变 | 最近节点摘要、近期节点列表、详情时间线 |

节点和主任务完成状态仍独立，界面明确这一点。不根据整项任务完成自动改写节点，不把跨日日期任务解释为全天占用，也不将节点定义为子任务重新建模。

分类颜色只负责区分类别；紧迫程度通过文字和截止标记表达，避免整条任务同时承担“类别颜色”和“紧急颜色”两种含义。完成状态使用可读的状态标记，减弱显示时仍保证文字可辨认。

## 6. 任务与确认流程

统一任务详情面板：标题与状态、计划时间、截止、节点、备注，随后才是操作。内容编辑和调时从同一个面板进入，并共享关闭、错误、保存反馈规则；可以继续保持分别保存，以免扩大后端改动。

创建任务先展示“名称 + 计划时间”，分类提供默认值，DDL、节点、简称和备注折叠为可选内容。如果保留两步，第一步只处理必要信息，第二步展示完整摘要，避免反复回退查字段。

确认按照后果设计：普通查看与无修改关闭直接完成；未保存改动关闭时明确“继续编辑 / 放弃修改”；删除、课程取消/恢复、权限变更展示具体对象和影响。确认留在当前面板，不能只显示一个远离对象的“直接确认”。保存中的按钮、保存成功、失败和版本冲突使用统一反馈；本轮只提出规则，没有对写入流程作实测结论。

## 7. 筛选、空状态和只读页面

所有视图保留清晰的筛选摘要和“清除筛选”。统计要么明确为全学期，要么跟随当前范围；禁止没有说明地混用。搜索需要先决定覆盖任务还是全日程，推荐默认任务搜索，同时涵盖简称、节点名；若扩展到课程和手记，应显示结果类型。

区分无安排、筛选无结果、未导入课表、无分享授权、今天超出授权范围、加载失败六种状态。每种状态解释原因；只读页只能提供清除筛选、日期导航等只读操作。

分享管理先显示“谁在看、可以看什么、日期范围、当前状态”，然后进入权限编辑。预览明确说明使用已保存设置；仅占用模式去掉缺乏意义的任务搜索及完成筛选，并说明日期安排不代表全天忙碌。Token 配置进入独立高级区域。

## 8. 实施顺序与验收

1. **先确认布局和规则**：确定默认视图、三个时间概念的名称、统计范围、搜索范围、详情形式。产出桌面和手机的首页/详情草图，不修改数据结构。
2. **整理阅读体验**：解决顶部遮挡，增加本周入口，整理今天排序、近期节点、筛选摘要、空状态及手机分区。先使用固定样例在本地验收。
3. **统一操作体验**：整理任务详情、内容编辑、调时、关闭与确认，再整理课表、分享和设置。只有明确授权后才在隔离数据上验证写入。
4. **整理前端结构**：按状态与筛选、日期/截止、课程、任务详情、确认、渲染、导出划分职责。逐步归并重复 CSS 覆盖和重复弹窗规则；不在一轮中重写数据库或更换框架。PNG 使用独立渲染路径，后续需专门保证与页面的信息口径一致。
5. **审核后发布**：按阶段提交、审阅；获得部署授权后备份并发布，生产仍先做只读验收。

验收清单：

- 390px、768px 与常规桌面宽度下，导航和主题入口不重叠；弹窗关闭和主要操作可见。
- 默认页直接看到当前范围；今天页的课程和定时任务按时间排序，长期任务有独立位置。
- 计划起止、最终截止、节点时间各自可辨；跨周/学期外、无 DDL、多节点、已完成等状态都能正确阅读。
- 当前筛选与统计范围清楚；无匹配不会呈现为“今天没有安排”；清除筛选有明确入口。
- 未修改关闭不确认；放弃修改、删除和权限变更确认可读且位于上下文内。
- 所有者、普通账户、展示账户、仅占用预览和管理员的可见操作符合各自职责。
- 浅色、深色与键盘焦点在后续完整验收中覆盖；写入验证只使用获准的隔离数据。

本方案不附真实任务、手记正文、凭据或账户详情截图。后续草图使用虚构示例，避免将私人内容带入可提交文档。
