# 新版前端与过渡

## 设计主线

总览使用有限的视觉容量承载摘要，详情通过浅层导航展开，操作通过原位确认保护。页面纵向长度与操作入口深度需要同时控制：不能靠无限增高任务块展示信息，也不能把常用操作藏进多层菜单。

首版提供三个视图：今天、本周、学期。桌面默认本周，手机直接进入今天。视图切换、定位今天和筛选入口常驻；具体筛选按需展开。桌面持续任务按照日期区间排入可共用的轨道，电脑端高度固定 44px（手机 48px），顶部是名称与计划/截止摘要，底部是节点轨道；节点名称、日期、时刻和状态紧邻标记。相近节点合并并显示额外数量，过密标签只保留标记，完整内容在任务详情的节点页查看。手机本周用七个日期标签切换单日，避免默认铺开七天的全部内容。

今天页支持前后一天导航。日程混合课程和定时任务并按时间排序，持续任务在同页独立区域并列，手机上下排列。未完成的逾期与当天截止、节点进入独立待办提醒区，完成后自动消失；手记保留同层标签。电脑端学期页默认展开全部周；手机保留按周折叠，默认展开当前周，学期外任务保留独立入口。每日任务和课程完整显示，不以“另有 N 项”截断。统计明确为全学期，采用四张紧凑卡片、标签与数字分层，并恢复学期进度条；搜索覆盖标题、简称、备注和节点名称。

任务详情分为概览、节点、备注；同一窗口切换标签时保持外框尺寸与操作区位置，长内容在内部滚动。编辑、调时、完成与删除直接可达。创建和编辑使用内容、时间、节点、确认提交四个同层标签，共用草稿，只有最终确认页可以提交。账户设置以修改用户名/修改密码标签替代操作下拉菜单，个人资料有直接入口，管理员操作进入账户管理。课程以我的课表/公共模板/临时调整/管理员模板管理分层，模板管理内再用课程模板、停课日期标签。课程取消为独立按钮，调整表单只编辑日期与时间。分享使用账户列表和单账户编辑页，编辑页分分享范围、展示内容、Dashboard 接入。管理员创建、绑定与登录状态管理集中到账户管理的展示账户页。

关键操作沿用按钮首次点击、原位滑块再次确认的机制，并保留角落低调的直接确认。确认对象和影响在当前上下文中说明；键盘可以用右方向键后 Enter 完成第二次确认，Esc 取消。无修改关闭分类管理直接退出；有未保存修改才确认放弃。

需要验证当前密码的操作使用独立身份验证窗口，暂时替代业务表单，取消后恢复原表单。当前密码只用于此次提交，不保存在浏览器存储，不默认短时免验证。服务端仍使用既有接口对密码、权限、CSRF 和提交内容进行检查；没有新增绕过验证的接口。前端收集身份凭据与后端验证/变更属于同一次受保护提交。

图标以本地 SVG 路径构成一致的线条系统，与功能文字配合使用；没有引入外部图标网络依赖。

## 入口与备份

2026-10-14 根据首轮使用反馈调整：每日安排不再截断，电脑端学期默认全部展开；新版设为默认首页。统计从通栏恢复为低高度卡片，旧版入口降为无边框的小号文字链接。低频设置与导出移入独立的同层标签窗口，侧栏不再展开整排操作。内容切换统一使用标签栏和选中下划线。深色日历采用中性底色，今天只在日期标题处强调；课程没有嵌套深色按钮底，任务分类色采用轻染与边线。普通任务、课程和持续任务采用一致的紧凑两行布局，电脑端 44px、手机 48px。任务详情、账户与课程窗口在同层标签切换时保持尺寸；任务详情的长内容在内部滚动，底部操作区保持原位。

| 路径 | 行为 |
| --- | --- |
| `/` | 新版默认首页，提供旧版切换入口 |
| `/next/` | 新版前端，提供“切回旧版”入口 |
| `/legacy/` | 旧版快照，仅适配本地资源路径及新版入口 |

三个入口共用现有登录会话和后端数据。切换版本不会复制、迁移或删除日程；两版的修改都会写入同一账户的数据。新版作为默认首页；旧版始终保留独立入口，不移除。

`static/legacy/original.html` 是改造前首页原文件；其他原资源保存于同目录，`SHA256SUMS.json` 记录原文件哈希。`legacy/index.html` 为可访问的适配入口。新版使用可维护的 `/app.js` 业务客户端（从冻结副本承接），再由 `static/next/app.js` 提供新的呈现与交互层；这是保留既有功能的过渡结构，后续可逐步提取独立模块。

此次后端改动仅增加静态资源白名单路由。Dashboard 节点兼容改动先以 `cc73242` 单独提交。现有密码校验、分享过滤、课程例外、任务版本检查与数据语义保持既有规则。

## 部署与回退

部署前备份服务器代码和 SQLite 数据库，核对前后源码差异；停止应用服务后安装代码及资源，校验语法与文件哈希，再启动服务。发布后的生产验证以 GET 和只读浏览为主，不创建测试任务。

用户随时使用旧版入口继续工作。服务器发布失败时恢复部署前代码并重启；数据库备份单独保存，不因前端回退而默认覆盖发布后的新数据。

## 可配置导出（2026-10-18）

新版桌面与 `/m/` 共用独立导出面板，提供图片、自选 JSON 与完整 JSON 备份。日期和内容选择独立于网页筛选与分享设置；默认本周、全部分类、未完成任务及课程，正文默认关闭。逐条挑选可排除任务、课次与手记。手机返回、桌面关闭时释放预览和草稿。

`POST /api/export-preview` 使用当前会话及 CSRF，参数包括 `format`（`image` / `json`）、`range`（`week` / `two` / `semester` / `custom`）、`start/end`、`categories`、`done/notes/nodes/timetable/course_notes/homework/busy_only`、`journal`（`none` / `all` / `selected`）、`journal_dates` 和 `exclude_tasks/exclude_courses/exclude_journal`。所有者预览分享时另传 `preview_id`，服务端验证归属与当前授权；展示账户及分享预览仅允许图片。返回规范化 `range`、`selection`、`summary` 和筛选后的内容，无策略持久化写入。

所有者自定义日期允许学期外安排；任务匹配计划区间、截止或节点。只因时间点进入范围的任务以 `schedule_visible: false` 和空计划日期返回；跨界计划裁剪并标记延续。课程以 `course_key@original_date` 为课次选择键。仅占用模式在返回前脱敏，选择键也使用匿名值。

图片采用独立浅色日期清单或周历。清单宽 1200px、周历宽 1600px，最高 6000px，按日期或周分图，超长内容续页。预览直接读取最终 PNG Blob 的数据，遵守现有 CSP；下载前重新请求并比较内容，变化后要求核对新预览。自选 JSON 标为 `planner-selection-v1`，不带完整课程模板和例外；完整归档保留既有 `format: 1` 字段及语义，不应用筛选，也不增加导入恢复。

必要验证：临时数据库覆盖筛选、私人字段、原课次排除、仅占用脱敏及权限收紧；绘图测试覆盖长正文分页、页高和末尾内容保留；浏览器检查图片显示、JSON 选择联动与手机版返回。旧版快照保持原哈希。导出功能已部署至服务器。


## 任务暂缓（2026-10-19）

新版桌面左栏提供“暂缓任务”入口，手机总览提供“暂缓”标签。未完成任务可在详情中暂缓，新建时也可直接选择暂缓；暂缓列表沿用分类和搜索，每行可直接重新安排。暂缓内容编辑、复制和删除撤销保留状态与参考安排。

任务暂缓后，原计划起止、截止及完整节点保存到 `previous_schedule`，生效时间置空、节点置为空数组。快照只保留最近一次暂缓前的安排，不参与日历、提醒、工作量或统计。详情只读显示原安排，重新安排默认全部时间及节点留空，显式“带入原安排”后才填入草稿；保存成功后进入新日期的日程。

所有者 `/api/state` 的 `tasks` 继续只包含正常任务，新增 `deferred_tasks` 单独返回暂缓任务。任务增加 `deferred`、`deferred_at` 与 `previous_schedule`，复用 POST/PUT 和原有版本检查。现存任务迁移为非暂缓，数据保持不变；已暂缓任务更新时省略状态仍维持暂缓，恢复时必须明确提交新的截止和节点（允许空值）。旧版快照保持不变，仅显示正常任务，暂缓管理与包含暂缓数据的完整备份使用新版或手机端。

分享、Dashboard、按日期的图片和自选 JSON 导出不包含暂缓任务或原安排快照。新版及手机完整 JSON 备份在原有 `tasks` 数组中合并两组任务，保留状态与参考安排，沿用 format: 1 归档格式。


## 任务操作冲突（2026-10-21）

新版桌面和手机版在已有任务由未完成变为完成、且仍有未完成节点时显示独立冲突窗口，用户可取消或强制完成。强制完成只结束任务，不改变节点状态。删除任何未暂缓任务（包括已完成任务）同样显示取消／强制删除；暂缓任务沿用普通删除确认。取消、关闭和 Esc 保留草稿，删除成功仍可撤销。

PUT `/api/tasks/:id` 的 `force_complete` 与 DELETE 的 `force_delete` 为可选布尔参数，仅作用于本次请求，不持久化。业务冲突返回 409，`code` 分别为 `unfinished_milestones`、`task_not_deferred`；前端只对匹配的业务冲突显示窗口，明确确认后携带原版本重试一次。版本变化、权限和 CSRF 检查仍然生效。普通保存已完成任务、新建和 POST 恢复历史记录不触发完成转换检查。

新版桌面从 `/legacy/app.js` 切换至 `/app.js`，冻结旧版资源及哈希保持不变。旧版客户端受到相同后端保护并显示冲突错误，强制操作请使用新版或手机版。无需数据库迁移。本地验证使用隔离数据库；线上验收只读，不写入真实测试任务。
